01

PanelSafe

Breaker-board auditing from a single photograph.

A YOLO detection pipeline trained on a proprietary field dataset and scaled tenfold by a synthetic generator that crops annotated breakers, masks their backgrounds, and re-pastes them onto rail geometry in new arrangements. A spatial heuristic layer then groups detections into rails and snaps them to module widths. An HMM/Viterbi decoder encoding rail grammar was built too, and cut when held-out real photographs showed it lowered accuracy.

The interesting part is what went wrong. The model scored 92% and was visibly wrong in the field, confidently calling residual-current devices MCBs. The cause was a six-class rotation between the annotation tool’s classes.txt and the data.yaml training actually read; the model had faithfully learned the permutation. Rescored against corrected labels, that 92% was roughly 6%. The metric had never measured accuracy. It measured agreement with a broken ground truth.

02

PanelSafe Unifilar

Detection output to a schematic an inspector will accept.

Every electrical certificate filed in Spain legally requires a single-line diagram conforming to UNE-EN 60617 and ITC-BT-25. Drawing one by hand in generic CAD costs an installer thirty to forty-five minutes per board, back at the office, disconnected from the panel they just audited.

This engine takes the ordered device sequence from the detection pipeline and procedurally compiles it into vector SVG in under 500 milliseconds — symbols constructed mathematically rather than stamped from a library, with dynamic multi-pole rendering, a computed load schedule (cross-sections, conduit diameters, calculated power per REBT tables), and vector PDF export for regulatory submission.

Role
Sole engineer — topology inference, symbol engine, vector export
Stack
JavaScript · SVG · vector PDF · shorthand DSL with live re-render
Standard
UNE-EN 60617 · ITC-BT-25 — the symbol set Spanish inspection actually uses

04

Hermes

A containerised agent loop, and the failure mode that made it necessary.

An autonomous coding agent that runs sandboxed in its own container against local models served by Ollama. File operations are bounded to a single writable workspace with the harness schemas mounted read-only; when the agent needs a human it posts a clarification card to a review queue rather than guessing. A stuck-loop detector watches for repeated tool-call signatures and no-op edits and trips a circuit breaker before the run burns its budget.

It exists because of a benchmark result. Run against the real tool schemas, qwen3-coder:30b emitted its tool calls as prose — <function=…> in the message body — which the chat template silently dropped. The loop saw an empty tool_calls array, read that as the model having finished, and reported completed work it had never done. The same shape as the PanelSafe label bug: a green result agreeing with the wrong thing. Two fixes came out of it — scan message content for unparsed call markers and fail loudly, and stop assuming a bigger model is a better one. Re-running the three failing probes under fixed temperature and thinking settings scored 0 of 45, never once correct and never once varying, so it was not sampling noise.

05

LocalPulse

Five fitness subscriptions replaced by one service that never leaves the house.

A self-hosted nutrition, training and progress tracker for a whole household, built as an installable progressive web app over FastAPI and SQLite and deployed on my homelab behind Nginx. No build step, no external CDN, no telemetry. A local vision model estimates macros from a meal photograph, and nutrition questions are answered by SQLite FTS5 ranking curated sports-science articles with BM25, fused with the user’s own targets before synthesis. Everything else works with the model switched off: the workout designer falls back to a deterministic generator that never prescribes equipment the profile does not own.

The engineering is in the boundaries. Python’s SQLite driver blocks, so database handlers run in the thread pool, and no async handler awaits the model while holding a connection. Every query is scoped to a profile, and backup export writes an isolated database containing only the requester’s rows. That isolation is tested rather than assumed: the suite covers cross-profile access, per-profile PINs and export scope.
